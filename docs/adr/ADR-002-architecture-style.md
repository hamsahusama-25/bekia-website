# ADR-002 — نمط المعمارية: Modular Monolith + واجهة Next.js (PWA)

- **الحالة:** معتمد (Accepted)
- **المالك:** Seat 5 & Seat 6 & Seat 10
- **التاريخ:** 2026-11-01

## السياق

- 10 أشخاص يشتغلون بالتوازي على MVP قصير الأجل، بتلات واجهات مختلفة: شركة (ويب)، مندوب ميداني (موبايل)، أدمن (ويب).
- المندوب يحتاج الكاميرا والـ GPS، لكن الفريق مش هيبني تطبيقين Android/iOS في المرحلة دي.
- المشروع محتاج يشتغل عند أي عضو بأمر واحد.

## القرار

1. **Backend واحد (Modular Monolith):** Node.js + Express، منظم في وحدات (`routes/`, `middleware/`, `models/`, `lib/`) داخل عملية واحدة. المنطق القابل للاختبار منفصل كدوال نقية في `lib/`.
2. **Frontend واحد:** Next.js (App Router) يخدم صفحات الأدوار التلاتة. شاشة المندوب Mobile-first وتُثبَّت كـ PWA (manifest) وتستخدم الكاميرا والـ GPS من المتصفح.
3. **MongoDB + Mongoose** لقاعدة البيانات، لأن لدينا بيانات جغرافية (GeoJSON) واستعلام `$geoNear` الجاهز.
4. **Docker Compose** بثلاث حاويات (mongo / backend / frontend).
5. الـ browser يكلم `/api/*` على نفس origin الواجهة، و Next يحوله للـ backend.

## البدائل التي دُرست

| البديل | سبب الاستبعاد |
|---|---|
| Microservices | تعقيد تشغيل وشبكات وتتبع لفريق وزمن لا يحتاجونه؛ الحدود بين الوحدات لسه مش مستقرة |
| تطبيق موبايل Native/Flutter للمندوب | مضاعفة العمل والتوزيع؛ المتصفح يغطي الكاميرا والـ GPS |
| PostgreSQL + PostGIS | قوي، لكن الفريق ماشي على Mongo والمتطلب الجغرافي (الأقرب فالأقرب) متغطي بـ `2dsphere` |
| Next.js API routes بدل Express منفصل | يخلط الواجهة بالمنطق، ويصعّب توزيع العمل بين Seats 3-4 و 5-6 |

## التبعات

**إيجابية**
- كود واحد وأمر تشغيل واحد، وتبسيط الاختبار (`app.js` منفصل عن `server.js` فاختبارات الأمان بدون قاعدة بيانات).
- مفيش حاجة اسمها CORS ولا عنوان backend داخل كود المتصفح.
- مفيش تكلفة تطبيقات موبايل في المرحلة الأولى.

**سلبية / يجب مراقبتها**
- الـ monolith ممكن يتضخم؛ نحافظ على حدود الوحدات ونفصل المنطق عن الـ routes.
- عنوان الـ backend يُحقن وقت بناء الـ frontend (يحتاج إعادة build عند تغييره).
- الـ PWA بدون Service Worker: لا يعمل بدون إنترنت؛ أول تحسين متوقع لو المندوبين بيشتغلوا في أماكن ضعيفة التغطية.
- وجود قاعدة بيانات واحدة: نقطة فشل واحدة (مقبول في الـ MVP).
